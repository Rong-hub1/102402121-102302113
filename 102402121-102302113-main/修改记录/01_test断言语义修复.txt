------------------------
一、问题描述
------------------------
文件：test/test.html 第 145 行
测试用例「无命中返回空数组」使用 eq(r, []) 做断言。
eq 函数内部用 JSON.stringify 比较两个数组的内容是否相等，虽然对空数组来说
JSON.stringify([]) === JSON.stringify([]) 恒成立（都等于 "[]"），但这个断言方式
语义模糊——它只比较"内容相等"，不比较"返回值确实是数组"。如果 searchItems 未来
被意外改成返回 null 或 undefined，这个断言会因为 JSON.stringify(null)=="null"
而报出令人困惑的错误信息。

另外，test.html 第 236 行的 eq(back, sample) 也存在类似问题：它只验证内容，
没验证返回的是新引用（loadItems 应返回解析后的新数组，不应是同一个引用）。

------------------------
二、修改方式
------------------------
把 eq(r, []) 改为 eq(r.length, 0)，与同组其他测试（如第 129、132、137、141、
149、153、157 行）的断言风格统一——都用 .length 来验证数组数量，语义更明确。

------------------------
三、修改代码对比
------------------------
【修改前】test/test.html 第 143-146 行：

  test(G, '无命中返回空数组', function () {
    var r = S.searchItems(ITEMS, '不存在的物品xyz');
    eq(r, []);
  });

【修改后】test/test.html 第 143-146 行：

  test(G, '无命中返回空数组', function () {
    var r = S.searchItems(ITEMS, '不存在的物品xyz');
    eq(r.length, 0);
  });

------------------------
四、影响范围
------------------------
仅修改了单元测试的断言写法，不影响任何生产代码逻辑。
测试运行结果不变（仍然通过）。
