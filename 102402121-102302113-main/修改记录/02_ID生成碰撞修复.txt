=== Bug 修复记录 #2 ===
修复日期：2026-10-10
修复人：Agent

------------------------
一、问题描述
------------------------
文件：js/store.js 原第 54 行 createItem 内 id 生成逻辑

原代码：
  id: 'item_' + Date.now() + '_' + Math.floor(Math.random() * 10000)

存在两个问题：
1. Date.now() 精度是毫秒，同一毫秒内连续调用 createItem() 会产生相同前缀
2. 随机数范围 0-9999，碰撞概率 1/10000

实际场景：用户快速连续发布两条信息时（或页面短时间内多次触发 createItem），
存在极低但非零的概率生成重复 id。重复 id 会导致 markDone / removeItem /
incrementViews 等按 id 操作的函数同时修改/删除多条记录，破坏数据一致性。

------------------------
二、修改方式
------------------------
在 IIFE 作用域顶部新增自增计数器 ID_COUNTER（初始值 0），每次 createItem 时
先自增再拼接时间戳。这样：
- 同一次浏览器运行内，自增计数器永不重复 → id 永不碰撞
- 即使刷新页面计数器重置，时间戳仍然递增（除非系统时间倒退），实际冲突概率为零
- 不依赖 crypto.randomUUID() 等较新 API，兼容性覆盖所有现代浏览器

------------------------
三、修改代码对比
------------------------
【修改前】js/store.js 第 9 行 + 第 54 行：

  var STORAGE_KEY = 'lost_found_items_v1';

  ...

      id: 'item_' + Date.now() + '_' + Math.floor(Math.random() * 10000),

【修改后】js/store.js 第 9-11 行 + 第 56 行：

  var STORAGE_KEY = 'lost_found_items_v1';
  // 自增计数器，确保同一次运行内生成的 id 永不碰撞
  var ID_COUNTER = 0;

  ...

      id: 'item_' + (++ID_COUNTER) + '_' + Date.now(),

------------------------
四、兼容性说明
------------------------
该改动仅使用 ES5 语法（自增运算符 ++、字符串拼接），所有现代浏览器（含 IE9+）
均支持。无需引入 polyfill，也不改变对外 API。

------------------------
五、影响范围
------------------------
仅影响 createItem 生成的 id 格式，不影响已有数据（已有 id 如 seed_1、item_1_xxx
均保持原样）。持久化的 localStorage 旧数据可正常读取、修改。
单元测试中「两次创建 id 应不同」用例仍然通过。
